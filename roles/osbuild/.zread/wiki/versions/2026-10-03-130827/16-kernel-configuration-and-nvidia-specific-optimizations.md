This page details how the **osbuild** role configures the Linux kernel and applies NVIDIA-specific optimizations for GPU-enabled systems. It covers kernel command-line arguments, driver integration, repository management, and the **NVIDIA CDI (Container Device Interface)** setup for GPU passthrough in containers.

---

## Kernel Configuration for NVIDIA GPUs

The role dynamically injects **kernel command-line arguments** to optimize NVIDIA GPU behavior during early boot and runtime. These arguments are defined in the `nvidia` component and applied to the blueprint's `[customizations.kernel]` section.

### Kernel Arguments
The following arguments are added to the kernel command line to ensure compatibility and performance with NVIDIA GPUs:

| **Argument**                     | **Purpose**                                                                                     | **Impact**                                                                                     |
|----------------------------------|-------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------|
| `rd.driver.blacklist=nouveau`    | Blacklists the open-source Nouveau driver during the initramfs (dracut) stage.               | Prevents conflicts between Nouveau and NVIDIA's proprietary driver during early boot.       |
| `modprobe.blacklist=nouveau`     | Blacklists the Nouveau driver at the kernel module level.                                      | Ensures Nouveau is never loaded, even if requested by other processes.                        |
| `nvidia-drm.modeset=1`           | Enables DRM (Direct Rendering Manager) kernel mode setting for NVIDIA GPUs.                   | Improves display output and performance for NVIDIA GPUs in graphical and compute workloads. |
| `DRACUT_NO_XATTR=1`              | Disables extended attributes (xattr) in the initramfs generated by dracut.                     | Avoids issues with NVIDIA kernel modules that may not support extended attributes.          |

These arguments are **dynamically compiled** from all selected components (including `nvidia`) and injected into the blueprint TOML file under `[customizations.kernel]`.
**Sources**: [defaults/main.yml](defaults/main.yml#L280-L285), [templates/blueprint.toml.j2](templates/blueprint.toml.j2#L40-L50)

## NVIDIA Driver and Package Integration

The `nvidia` component includes a **curated set of packages** to support NVIDIA GPUs, CUDA, and container tooling. These packages are automatically included when the `nvidia` component is selected in `osbuild_components`.

### Package Taxonomy
The following packages are included for **Fedora** (similar taxonomies exist for AlmaLinux and Rocky Linux in their respective files):

| **Category**               | **Packages**                                                                                     | **Purpose**                                                                                     |
|----------------------------|--------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------|
| **Driver**                 | `nvidia-driver`, `nvidia-driver-cuda`, `nvidia-driver-libs`, `nvidia-kmod-common`              | Proprietary NVIDIA driver and its dependencies.                                                |
| **CUDA**                   | `cuda`, `cuda-toolkit`                                                                           | NVIDIA CUDA toolkit for GPU-accelerated computing.                                            |
| **Container Toolkit**      | `nvidia-container-toolkit`, `nvidia-modprobe`                                                  | Enables GPU support in containers (e.g., Podman, Docker).                                     |
| **Firmware**               | `nvidia-gpu-firmware`                                                                           | GPU firmware for NVIDIA devices.                                                               |
| **Persistence**            | `nvidia-persistenced`                                                                           | Manages GPU persistence mode for improved performance in compute workloads.                  |
| **Kernel Modules**         | `kmod-nvidia-open-dkms`, `dkms`                                                                 | DKMS-based kernel modules for NVIDIA GPUs.                                                     |
| **Utilities**              | `nvidia-settings`                                                                               | GUI and CLI tools for configuring NVIDIA GPUs.                                                |

**Sources**: [vars/packages/Fedora.yml](vars/packages/Fedora.yml#L80-L95), [defaults/main.yml](defaults/main.yml#L270-L290)

## Repository Management for NVIDIA

The role automatically configures **repository sources** for NVIDIA drivers, CUDA, and container tooling. These repositories are added to the blueprint and are distribution-aware (Fedora vs. EL-family).

### Fedora Repositories
For Fedora-based systems, the following repositories are added:
1. **RPM Fusion Nonfree NVIDIA Driver**:
   - Base URL: `http://download1.rpmfusion.org/nonfree/fedora/nvidia-driver/{version}/{arch}/`
   - GPG Key: `https://rpmfusion.org/keys/RPM-GPG-KEY-rpmfusion-nonfree-fedora-2020`
2. **NVIDIA CUDA**:
   - Base URL: `https://developer.download.nvidia.com/compute/cuda/repos/fedora{version}/{arch}/`
   - GPG Key: `https://developer.download.nvidia.com/compute/cuda/repos/fedora{version}/{arch}/1940C73E.pub`
3. **NVIDIA Container Toolkit**:
   - Base URL: `https://nvidia.github.io/libnvidia-container/stable/rpm/{arch}/`
   - GPG Key: `https://nvidia.github.io/libnvidia-container/gpgkey`

### EL-Family Repositories (AlmaLinux/Rocky)
For EL-based systems (AlmaLinux/Rocky), the following repositories are added:
1. **RPM Fusion Nonfree NVIDIA Driver**:
   - Base URL: `http://download1.rpmfusion.org/nonfree/el/nvidia-driver/{version}/{arch}/`
2. **NVIDIA CUDA**:
   - Base URL: `https://developer.download.nvidia.com/compute/cuda/repos/rhel{major_version}/x86_64/`
   - GPG Key: `https://developer.download.nvidia.com/compute/cuda/repos/rhel{major_version}/x86_64/CDF6BA43.pub`
3. **NVIDIA Container Toolkit**:
   - Same as Fedora.

## NVIDIA CDI (Container Device Interface) Setup

The **NVIDIA CDI** feature enables **GPU passthrough** to containers (e.g., Podman) by generating a **CDI specification file** (`/etc/cdi/nvidia.yaml`). This allows containers to access the host's NVIDIA GPUs securely.

### Architecture
The CDI setup consists of:
1. A **Bash script** (`nvidia-cdi-generate.sh`) that:
   - Waits for NVIDIA device nodes (e.g., `/dev/nvidia0`) to appear.
   - Generates the CDI specification using `nvidia-ctk cdi generate`.
   - Writes the output to `/etc/cdi/nvidia.yaml`.
2. A **systemd service** (`nvidia-cdi-refresh.service`) that:
   - Runs the script at boot (`After=network-online.target`).
   - Ensures the CDI specification is regenerated if the GPU state changes.

### Workflow
```mermaid
graph TD
    A[System Boot] --> B[network-online.target]
    B --> C[nvidia-cdi-refresh.service]
    C --> D[/usr/local/bin/nvidia-cdi-generate.sh]
    D --> E{Check /dev/nvidia0}
    E -->|Exists| F[nvidia-ctk cdi generate]
    F --> G[/etc/cdi/nvidia.yaml]
    G --> H[Podman Containers]
    H --> I[GPU Access]
    E -->|Not Exists| J[Error: GPU Not Found]
```

### Script Details
The script (`nvidia-cdi-generate.sh`) includes:
- A **30-second timeout** to wait for `/dev/nvidia0`.
- Error handling for missing GPUs, drivers, or failed compilation.
- Logging to the journal via `StandardOutput=journal` and `StandardError=journal`.

## Build-Time Integration

### Blueprint Generation
The `blueprint.toml.j2` template dynamically:
1. Compiles **kernel arguments** from all components (including `nvidia`).
2. Injects **NVIDIA-specific files** (CDI script and service) if the `nvidia` component is selected.
3. Includes **packages** and **repositories** from the `nvidia` component.

**Example Blueprint Snippet**:
```toml
[customizations.kernel]
append = "rd.driver.blacklist=nouveau modprobe.blacklist=nouveau nvidia-drm.modeset=1 DRACUT_NO_XATTR=1"

[customizations.services]
enabled = ["nvidia-cdi-refresh", "nvidia-persistenced"]

[[customizations.files]]
path = "/usr/local/bin/nvidia-cdi-generate.sh"
mode = "0755"
data = '''
#!/bin/bash
# NVIDIA CDI generation script
...
'''
```
**Sources**: [templates/blueprint.toml.j2](templates/blueprint.toml.j2#L40-L130)

### Build Process
The `build.yml` task includes a **hardcoded NVIDIA CUDA repository** for Fedora to ensure the latest drivers are available during the build:
```yaml
--extra-repo "https://developer.download.nvidia.com/compute/cuda/repos/fedora43/x86_64"
```

## Validation and Dependencies

The `nvidia` component is validated for:
1. **Schema Compliance**: Ensures all required fields (e.g., `label`, `packages`, `requires`) are present.
2. **Dependencies**: Requires the `base` component (for core system packages).
3. **Conflicts**: Currently has no conflicts but can be extended to exclude incompatible components (e.g., `nouveau`).
4. **Secure Boot**: Marked as **not compatible** with Secure Boot due to NVIDIA driver signing requirements.

**Sources**: [tasks/validate_components.yml](tasks/validate_components.yml#L1-L69), [defaults/main.yml](defaults/main.yml#L288-L289)
